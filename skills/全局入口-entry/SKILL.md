# 语义规则工作台（全局调用入口）

适用于设计智能体、原子化规则、建立世界模型、改规则、诊断问题、查历史与验证。用户不填写内部编号或结构化文件，助手负责实际操作。不要把工作台调用固定解释为案例检索。

## 先识别任务，再调度（不能跳过）

读取核心技能的总入口规则，按用户的目标而不是材料类型选择能力。用户给了一个案例，但要求建立世界模型，应走世界模型，不是默认案例诊断。

- Agent设计：职责、输入输出、允许动作、禁止项、完成条件与可用候选指令。
- 规则原子化：维护单位、联合条件、例外、来源对应和身份承接。
- 世界模型：对象、状态、关系、动作、权限、转换、不变量和证据。
- 规则变更：原义、候选改稿、含义变化、保持不变、影响及验证预期。
- 案例诊断：只有需要判断重复问题与经验适用性时，才调用现有Semantica（决策关系组件）检索流程。
- 历史回查：读取记录，不新建一个案例去重新猜旧决定。
- 回归验证：组织固定预期、场景、实际观察与证据，不把提出测试方案说成已运行。
- 授权实施：当前执行器未接通，必须报告未执行，不写业务文件，不用分析产物代替实际实施。

助手先用`能力`查看真实入口，按意图选择`总入口 --请求 ... --能力 ... --依据 ... --材料 ...`。能力选择由当前智能体完成并记录理由，不是关键词分类器，也不要让用户替助手选内部模块。目标有实质歧义时只问该歧义。

设计、原子化、世界模型、变更与回归可按用户要求组合。`提交专项`校验当前产物后，返回下一能力及前序产物；按顺序实际完成，直到`专项报告`交付。案例诊断、历史回查分别复用已有执行入口，取得结果后再作为其他专项的材料续接。不能为了凑一条流水线强制调用全部能力。

## 项目隔离与调用

1. 先确定当前业务项目根目录，所有命令显式携带`--项目 <当前项目绝对路径>`。不要为了调用程序把当前业务项目误设为工作台自身，也不要以附件所在目录作为项目根。
2. 用`项目状态`核对项目及数据位置。默认每项目独立数据库，案例、规则、证据、决定和检索范围不混用；不传`--数据目录`指向别的项目库。
3. 示例（由助手替换路径并执行，用户无需敲命令）：

```powershell
& 'C:\AI\yuyigongzuitai\.环境-venv\Scripts\python.exe' -X utf8 -B 'C:\AI\yuyigongzuitai\工作台.py' --项目 '当前业务项目绝对路径' 项目状态
& 'C:\AI\yuyigongzuitai\.环境-venv\Scripts\python.exe' -X utf8 -B 'C:\AI\yuyigongzuitai\工作台.py' --项目 '当前业务项目绝对路径' 总入口 --请求 '用户的实际问题' --能力 规则原子化 世界模型 --依据 '用户明确要求原子化后建模' --材料 '用户材料文件'
```

4. 按所选能力完成实际设计、建模、改稿或诊断，提交对应产物并交付中文报告。只有案例诊断分支使用检索、提交审阅和案例报告；其他分支使用专项提交与报告。不能只登记任务、给出路由或填空模板就说能力完成。
5. 只有用户明确要求参考另一个项目时，才用`跨项目参考 <那个项目的绝对路径> [--编号 <记录编号>]`。结果是只读外部参考，不导入规则、不授予执行权限；外部编号不能直接作为本项目规则或证据引用。
6. `历史回查`只用于用户明确要求的隔离前混合试点记录，不进入任何项目的默认检索。

## 权限与真实性

- 全局技能可发现不等于获得文件系统权限。任务必须能读取工作台源码并写入其`数据-data/项目-projects`下对应数据目录；权限不足按当前工具审批流程申请，不修改沙箱策略或绕过限制。
- 不修改全局凭据、生产规则或远端项目。业务写入仍需要明确授权；跨项目参考本身不授权生产操作。
- 用户明确“只读、不保存”时保持只读分析，不运行写入流程。
- Semantica（决策关系组件）负责候选检索，智能体负责语义判断；不把相似度、结构校验或历史待审决定冒称批准或根因证明。
