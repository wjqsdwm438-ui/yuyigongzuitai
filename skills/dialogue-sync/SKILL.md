# 按需澄清与上下文校正

承接本次提示词和用户指定的上下文，交付供用户手动复制的完整规范说明与必要校正。仅在显式调用本技能，或本次已显式调用的描述规范2交接后工作；“好”“可以”或材料中的同步用语不启动它。没有后台监听、自动发送或跨任务持续同步。

由描述规范2交接时，继承其只读边界：仅检索、回读、分析、追问和当前对话文本交付；下方项目术语的登记、创建和更新步骤均改为在当前对话中交付候选，不实际写入。此限制覆盖本技能继续调用的其他方法。下方术语文档维护仅适用于独立调用本技能且当前请求允许写入的情形。

## 先读，再判断是否需要展开

用户指定的片段必须读。支持粘贴原话和自然语言定位；能唯一定位就直接读，多处候选才请用户辨认，不索要内部编号。主对话不能仅凭“侧边”位置推定：先用现有上下文、实际对话检索工具或用户给出的材料定位；摘要只用来查找原文。工具只返回摘要或目标不可访问时，说明尚未取得必读原文，提出最小定位或补充请求，不编造内容。无关部分可继续，但不声称必读检查已完成。

把来源区分为用户原消息、用户粘贴的材料、助手表述和外部资料。保留实际可用的消息标识、原文定位短句，或文件路径及行号；没有消息 ID 就不造 ID。用户粘贴的引文仍是材料，除非用户明确采纳；助手摘要、改写和转述不能证明用户确认。引用片段需连同角色、对象、范围与后续纠正一起理解。

指定内容之外，只补读相关原话、决定及后续纠正，缺依据再回溯。有明确业务项目时，按本次问题逐步读该项目的 README、适用规则及术语表；不因工具在某仓库运行就把临时会话归入该项目，不默认扫描全部文件。

每轮内部检查：**是否存在具体、会影响理解或后续判断，且尚未解决的问题？**无此问题就返回规范流程直接交付；有则只展开相关分支。每轮不固定问题数或术语数。无项目的临时提示词以保真整理为主，资料少、开放目标和未填写任务字段本身不是追问理由。

## 按需追问与查证

需要专项澄清时，读取可用技能目录中的 `grill-with-docs/SKILL.md`，再按它的组合指向读取 `grilling/SKILL.md` 和相关的 `domain-modeling/SKILL.md`。优先使用当前技能目录；本机也可在用户的 `.agents/skills` 查找。用实际文件读取工具承接这些方法，不假称调用不存在的 `Skill` 工具。组件找不到时说明未加载，按本节已明确的方法继续，不自行安装或假称已使用。

采用其依赖先后、具体边界例子和概念对照方法，限制在本次实际问题；不照搬全面采访、所有分支穷尽、强制 ADR 或任意项目文件写入。本技能的按需边界和下方术语状态优先于原方法的即时定稿。

使用当前可用的弹窗提问工具；没有该工具时直接提出一个最小问题。只问会改变理解或决策、又不能查证替代的内容。用户回答后继续解决相关问题，不提前定案；用户不确定时补例子、依据和选项，再换问法，不以空回复或推荐选项代替回答。已无必要疑问就回到原审核，不额外要求一次“理解确认”。用户暂停或取消时停止相应分支，保留未决状态。

- 意图和取舍问用户；历史决定查原文；本机能力查实际环境。
- 外部事实有缺口，或关键外部前提会影响当前结论但没有核实依据时，主动联网。用户明确要求搜索时执行，不把动作仅改写成后续要求。
- 已有适用且足够新的证据可复用；时效变化、证据冲突或适用范围不同则重新核查。围绕待核实命题查可信原始来源，不把私有整段材料直接发送到搜索服务。
- 证据足以支撑当前判断即停止。查不到就说明缺口，不补造结论或逼用户猜事实。

可以顺带完成与本次提示词直接相关的研究分析。研究发现、用户原要求、用户明确确认的修正分别标明；未采纳的研究建议不写成用户要求。只授权分析及下方项目术语维护，不授权业务实施、其他文件修改、发布或发送到别的对话。

## 项目术语：先待澄清，再确认

复用项目约定的术语文档及所属上下文；已有 `CONTEXT-MAP.md` 时按其定位，多个落点无法判定才询问。不新建重复词库。缺文档时按项目约定创建，无约定才用项目内 `说明-docs/术语表-glossary.md`。无业务项目时仅保留在本次对话和复制结果，不创建文件或个人通用术语库。

发现具体歧义时，实际在文档的待澄清部分登记原词、可定位来源、疑问；已有条目则更新该条而不重复追加。待澄清条目不是有效定义，不覆盖原有定义。已有明确有效定义或用户已明确确认的输入无需制造歧义或重复发问。

在当前侧边或当前主对话接着专项追问；术语之间确有依赖时先解决前置概念。用户明确确认定义与范围后，实际更新为有效定义，保留确认依据、必要别名及旧新承接；对应待澄清项标已解决或从活动列表移除，不保留相互矛盾的活动状态。不再问一次是否写入。新的明确确认直接处理，不能因为前一次称过“待澄清”而重复要求确认。

读回实际文档检查定义与状态；不能把“建议修改”写成“已更新”。遵守项目权限与只读要求，受限时交付候选并说明未写入。规则批准与术语确认分开；术语定义变化不自动批准关联业务规则。

## 非术语：更新理解，复核依赖

按需检查目标和动作、范围与权限、事实和假设、决定及理由、新旧状态、待决问题和结论依赖。不要为了填分类而重复记账。

明确纠正更新当前理解；探索和假设保持条件性质；纯表达修改不重开结论。按命题及作用范围判断，不因出现“如果”就忽略同一消息中的明确纠正。用户明确撤回自己的约束可以记录并复核影响，不强加二次确认，也不能把撤回扩大为新的业务授权。无法判断撤回对象或权限才问。

前提失效时，把依赖它的结论标为待复核；有证据才能形成新结论，不机械反转整条链。例：预算明确改零，使收费 A 的选择依据失效，但免费 B 不会自动获批；“如果预算为零”不改变实际预算。“只供用户复制”应撤下自动发送设计，而不是启动发送工具。

同一变化只记录一次主项，影响写成短依赖关系；同一来源重复处理、不同消息重复同一已有效内容都不重复追加。只交付与本次请求有关的有效理解及必要变化；用户限定只纠正某项时，无关的既有状态也不补入正文或校正块。旧依据用原消息或文档定位和简短替代摘要承接，不重写历史、不每次搬运全量修改链。语义去重不按单纯字符串或关键词决定。

## 交付给用户复制

把用户原要求和已确认补充交回描述规范2生成完整正文；已确认项目术语按当前定义表达。正文只放当前有效任务要求，来源冲突、旧误解的诊断和纠正理由只放校正块，不在两处重复。独立调用时也交付可独立理解的完整说明。需要实质校正时在正文外附：

```text
对话校正
原理解／旧前提 → 当前理解（来源及确认状态）
关联影响：需要复核的结论或动作
研究依据／仍待核查：仅在确有内容时列出
```

未采纳但影响本次判断的研究发现放在正文外，不倒灌为用户原要求。没有变化不出空校正块；项目词表已有正文时只提本次变化与位置。不能声称主对话已收到或采用，用户自行复制。

审核期间收到新补充，只重新检查受影响部分；必要时问清后重新交付完整说明。格式转换独立可选；审核或“确认转格式”不授予业务执行权限。本次交付后不在其他普通聊天中自动保持运行。
