# 行为对照与触发验证（仅评测组织者读取）

本文件供维护 `agent-rule-workbench`、测试这个技能本身的评测组织者使用。日常设计、审阅或验证用户规则时，用该目标自己的材料和场景，不进入本技能测试库。答题者只读取技能正文与不含预期的题面；组织者负责准备和评分，两者不混为同一次看答案再作答。

## 先验证实际结果，再作版本选择

本节适配已固定的 Anthropic `skill-creator`。组织评测时读取 [grader](../../../依赖-dependencies/技能上游-upstream/安索匹克-anthropic-skills/skills/skill-creator/agents/grader.md) 的实际产物与弱断言审查；需要匿名比较时读取 [comparator](../../../依赖-dependencies/技能上游-upstream/安索匹克-anthropic-skills/skills/skill-creator/agents/comparator.md)；结果解释时读取 [analyzer](../../../依赖-dependencies/技能上游-upstream/安索匹克-anthropic-skills/skills/skill-creator/agents/analyzer.md)。以下本地约定优先于上游的人机交互、计分和执行命令。

1. **固定可观察预期。** 来源是用户要求和有效规则，不是候选自述。准备原失败、正常行为与反例；按失败族保留一份不参与改稿或选候选的留出材料。注明真实来源、受控复现或合成，不把合成情境说成线上事故。
2. **检查“什么也不做”能否通过。** 获准改文件的任务要检查文件实际改变且满足要求；修复任务要让未修版本至少有一项失败。字符串非空、引用存在和候选自己选的示例不是完整评价。
3. **固定初始状态，隔离执行。** 旧版与候选各用一份相同初始工作区、同一题面/权限/模型设置。答题者只能读分配的技能、题面和工作区，不读预期、另一版输出或评分。已有代码允许执行时，要求真正改文件并运行检查，不把答题建议当实际修复。
4. **检查最终产物与轨迹。** 程序运行能确定的检查；审阅者核对中文含义、引用关联、额外义务及授权。核查实际工具调用和工作区，不只听执行者说已测试。未运行、环境失败、业务失败分别记；不把报错默认为算法失败，也不把它从样本中悄悄删掉。
5. **比较而不强行选赢家。** 量表先于答题固定，匿名审阅可以平局或证据不足；双方都不合格时不采用任意一方。发现量表外缺陷单独记录并阻断不合格候选，保留旧评分不造提升。通过后才使用最后的留出材料，不能将已用于选择候选的集再称最终未见测试。
6. **按可得证据解释差异。** 随机任务尽量重复相同配置；单次只报告单次。令牌、耗时、成本只记录实际提供的数据，缺失写未采集。查看两边都通过/失败的项目，不能用总分掩盖不区分版本的弱测试。结果未改善时不继续加指令追分。

助手完成基础核查与独立审阅后才向用户交付；不沿用上游“先让用户逐题挑错”作为必经阶段。业务取舍仍由用户决定；空反馈、没有回复、比较获胜均不代表满意、批准或可以发布。

## 触发与加载不是同一个测试

- **适用性检查**：用应使用、近似但不应使用的请求检验能力边界。文字分类正确只说明选路判断，不证明宿主会自动加载。
- **实际触发检查**：在目标宿主的新任务中，只提供技能目录/描述及普通请求，不直接要求读取某文件；从可观察调用验证是否读取正确 Skill 和必要参考。没有这种运行证据就标“原生自动触发未验证”。
- **使用效果检查**：显式给技能路径后的产物对照，证明的是加载后的行为，不冒充自动触发率。

上游 `run_eval.py` / `run_loop.py` 依赖 `claude -p`，不在 Codex 中假称直接可用，不为评测安装另一套 CLI。其每轮按 test 分数选择描述的集合在本地视为验证集，不是最终独立留出。所有上游脚本和模型调用另按实际环境与授权选择，不能执行原件中的安装命令来绕过边界。

## 保留旧决定回归（辅助检查，不替代以上结果验证）

### 运行

在本技能目录中，用可用 Python 运行：

```text
python 测试-tests/regression.py self-test
python 测试-tests/regression.py prepare
python 测试-tests/regression.py grade answers.json
```

`prepare` 输出不含标准答案的场景。让一个未读取 `测试-tests/cases.json` 或评分预期的独立助手读取本技能，处理这些场景，按输出约定保存答案，再执行 `grade`。准备输出和答案可以放在隔离的临时目录；不要覆盖正式规则。

这些命令不调用模型、网络或收费 API。模型回放另行使用已获准的执行方式。本包附带一次实际独立回放的答案和评分结果，可直接重跑评分。

### 检查什么

14 个场景分别覆盖普通确认、精确转换确认、附带修改、联合条件、例外、稳定身份、缺失理由、关联影响、未决状态、允许的新决定、引用命题、设计推进、主次和根因证据。

评分器检查指定决策字段和真实来源摘录，并检查设计案例是否交付必要正文。`decisions`只放每题fields列出的决定；required_text_fields列出的设计正文放在与proposal同级的顶层字段。它不是自然语言等价判定器：引用存在不证明引用相关，正文非空不证明设计好，结构化决定正确不证明自然语言建议完全一致。还须阅读实际 proposal 与设计文本核对这些部分。

判定采用逐例通过／失败／未运行，不以概率或综合分数批准规则。未知或重复案例、缺失答案、非法类型及虚构来源都会报错或失败。评分结果的 `automatic_approval` 始终为 false。

### 真实项目如何延伸

本套测试先覆盖本技能的决策边界，不代替实际项目回归。实际项目还需固定已确认输入、正式规则版本、工具与权限，比较：

1. 修改前与修改后在原失败场景、正常场景及未用于优化的新场景上的行为。
2. 同一规则与必要关联一起加载后的实际动作和产物，而不只是模型填写的决定。
3. 用户审核分钟数、实质返工次数、回翻材料次数，以及新增记录本身的维护时间。

允许的新业务决定需明确更新预期；不要以旧测试固化已被用户改变的需求。没有实际记录就报告“减负效果未验证”，不估算一个漂亮百分比。
