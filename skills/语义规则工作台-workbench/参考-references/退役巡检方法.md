# 指导规则退役巡检方法

## 处理对象与动作边界

处理具体指导段落及其标题、例外、共享定义与依赖，不默认删除整个 Skill。历史记录中的旧义可以正确反映当时决定；应先取消其活动入口效力，而非改写历史。词频、年龄、相似文本、未被近期调用、断链均不是单独的退役依据。

## 完成一次巡检

1. 以当前项目根调用 `退役巡检`，默认只读。扫描 Agent 指令、Skill 正文与参考、元数据指针，并递归读取项目内关联的文本依据。归档、业务数据、运行目录、第三方与测试样本不进入默认活动区；越界、符号链接、编码和容量缺口必须说明。范围只限当前仓库；部署副本不在本期范围。
2. 先查确定性信号，再对无信号的待复核段落做有界语义检查：这段今天仍解决什么问题？支持它的依据是否仍有效？新决定是否明确替代全部或部分？是否只是历史描述、反例或低频例外？当前消费者是否仍需要它？外部事实未知时查原始来源，不能由文字推定现状。
3. 获准保存时用 `--记录`，根据返回的 `审阅模板` 填写并调用 `退役审阅 <文件.json>`。结论为保留有效、建议退役、历史保留或证据不足；必须填写依据、适用条件与例外、替代与消费者、验证与边界以及本次真实来源摘录。保留结论默认30天复审，证据不足默认7天，最多90天；依赖变化优先重开。日期是复查期限，不是自动删除日期。
4. 只向用户交付最重要的3–5项，固定问题、依据、推荐、是否需要你决定。未解决的事实先自行补核；只有实质业务取舍或授权才交用户。其他待复核段落仍在项目库或扫描包，不伪称全部已完成语义审阅。
5. 已授权的段落改稿使用现有规则变更与回归验证；整文件归档/删除使用原生治理预演和精确授权。改后重新扫描实际文件与消费者；保留之前的证据和审阅。建议退役不会消失为“已完成”，提交成功也不表示文件已改。

## 持续触发

当前智能体在指导规则维护和相关反馈任务中执行此模式。仓库 `Retirement watch` 初始只允许在 main 上手动派发，并要求本次 Issue 写入的显式授权；main 变更与周期触发尚未启用。它恢复同一云端项目库并维护一个通知索引，没有变化不另建通知；会发现明示退役的活动引用和结构信号，并把含义待核的无信号段落纳入复审，不会独立完成开放中文判断。

本地库与云端库是独立运行实例，不自动互相导入。云端产物最多保留90天；记忆缺失时明示重新全量复核，损坏时停止。首次手动运行通过后，是否启用周期触发另行授权；应查看实际工作流状态，不能把配置文件存在当作持续运行证据。

## 最小验收

正例：断链、明示退役仍被引用、链接正常而指导要求与依据冲突。反例：低频例外、历史引用、否定“退役”、模板文件名。恢复：重复扫描不重复存证，同一审阅可重试，同位置正文或多跳依据变化重开，到期复查；旧快照不覆盖。边界：条目身份使用相对路径、从 H1 到当前节的标题文本路径及本节段落序号，正文和依赖只进入绑定版本。改标题、移动、拆合及前置插入/删除可能改变续接标注，但文件版本变化后所有受影响条目必须重新复核，不能沿用旧处置压制。默认只读无文件变化，跨项目及符号链接不读取，无生产写入或自动删除。
