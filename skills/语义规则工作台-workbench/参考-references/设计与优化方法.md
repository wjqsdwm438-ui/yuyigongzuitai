# Agent / Skill 设计与优化（本地适配）

本页只保存工作台采用的增量方法；权限、来源保真、规则维护和交付要求以核心 Skill 与通用 SOP 为准，不在此重复。方法来源为仓库固定的 Sentry `skill-writer`、`prompt-optimizer` 和 Anthropic `skill-creator`，并吸收本机正式 `writing-for-agents` 的 Agent 文档结构原则。后者由作者技能仓库维护，可按环境自动触发，但不是本仓库运行依赖；上游全文只用于维护和追溯，不因引用存在而在日常任务中全部加载。

## 结构与落点

- 先写明要改变的可观察行为、实际生效入口和完成证据；局部问题优先局部修改，反复失败才进入下节。
- 核对目标正文和实际加载输入，区分已读取内容、只出现路径或名称但未加载的内容及范围外内容；路径存在不表示内容已经进入 Agent 输入。
- Skill 的描述和文内链接都是调用指针：前置真正的触发分支，每个分支只写一次；仅在需要自动发现或被其他 Skill 调用时保留自动调用，具体元数据服从当前宿主规范。
- 按信息层级放置内容：所有分支共同必需的步骤留在核心，仅特定分支需要的参考放到条件指针后；同一概念的定义、规则和例外共置。拆分必须证明节省的上下文负载值得新增的人类索引负担。
- 每个含义只保留一个正式定义；命令、配置和目录等可直接查询的环境也是当前真源，不把便宜查询复制成易过期说明。新增规则前先找可替换、收窄或删除的旧规则，逐句删除重复、失效沉积和不改变行为的默认能力说明。
- 步骤使用清晰且覆盖完整的完成条件，步骤与按需参考分开；优先正向描述目标行为，仅把无法正向表达的硬门禁写成禁止。修改后重读实际入口及必要调用方，确认没有形成第二套真源。
- 固定步骤用流程，开放判断用 Agent；没有独立信息或权限需求不拆角色。所谓“更安全”若把正常任务改交人工、缩成少数模板或新增审批，视为功能退化。
- 已获准的本地维护不因工作台通用执行器未接通而停下；同时区分文件工具实际修改与工作台程序自动实施，不把一者冒充另一者。

## 反复失败时的优化循环

1. 固定任务契约、成功标准、旧版和失败输入；把修改中使用的工作集、回归集与最后才运行的留出集分开。
2. 沿“实际加载 → 判断 → 工具参数 → 应用结果”寻找第一个可观察偏离：加载或版本问题修入口，条件解释问题修指令，参数或成品问题修工具/实现，合法的新要求按来源更新预期；证据不足时先立可被推翻的假设和最小探针。
3. 指令瓶颈仍不明确时，比较两个针对同一根因且有实际差异的候选：一个最小修复，一个改变组织或必要示例。使用相同材料、权限、工具与模型设置；明确的工程故障不为凑候选而增加方案。
4. 先复查原失败，再查正常路径、条件翻转和近似反例；较好的候选最后通过未参与选择的新材料。需要证明行为改善时才读取 [行为对照与触发验证](regression.md)。
5. 每轮只改变一两个可解释因素，并记录假设、改动、结果及保留/拒绝理由。没有改善、行为来回摆动、正常路径退化，或证据指向加载、工具、模型或宿主状态时，停止改提示词并转修对应机制。

## 结果判定

- 检查实际输出、工具轨迹和最终状态，不以候选解释、结构通过或“已成功”自述代替结果。
- 旧版与新版都通过表示持平；用于选择候选的材料不再算最终留出。失败候选不覆盖有效版本，失败证据继续保留。
- 完成时必须得到具体行为差异、实际改稿或机制修复及对应运行结果；只读任务交付候选和证据状态，获准修改则交付实际文件差异。
