# 应退役内容主动发现：方案与验收

版本：v0.2.0。基线：`c6107c3e797d23a77a5f4d8b63afd5ac011918a1`。本次只改语义工作台，不改关联业务仓库或全局部署。

## 现状与缺口

现有工作台具备多来源专项、规则变更、回归验证、项目分库、只读与不可覆盖历史，以及确定性文件治理。核心 Skill 和审阅 SOP 已规定语义保真与改动前验证。缺口是没有可运行的指导段落巡检、跨次处置记忆与受控远端触发。通用业务规则写入执行器仍未接通，不把仓库治理误称为全部实施能力。

实际发现 README 宣称私有，而仓库元数据为公开。已更正当前入口，并明确早期私有状态是历史记录；没有更改可见性或删除历史。这是“链接仍正常、描述已不适用”的真实语义问题，不能靠断链检查发现。

首次干净环境运行既有38项 unittest：25通过，12错误、1失败；原因是测试临时目录前提和缺失Semantica。补齐隔离环境后，38项既有测试、独立规则检查及Skill自测通过。临时目录测试改用系统临时目录，不改变业务逻辑或降低断言；Semantica用官方公开导入，未用假组件冒充。

## 三段建议的比较与取舍

上下文可恢复的是“第一版、第二版、综合建议”三段建议，而不是三份完整独立产品。按明确提出的机制比较，不补造未提供的细节。

| 建议 | 采用 | 不足及处理 |
|---|---|---|
| 第一版：事件触发与处置记忆 | 段落定位、项目库、重复抑制、版本变化重开 | 仅做事件和指针检查会漏掉无结构异常的失效指导 |
| 第二版：变更连带与新增规则复审依据 | 多跳依赖版本、有限复审期限、按需记录依赖 | 仅看变化会漏掉第一次扫描前已过时的材料；不强制每句话加元数据 |
| 综合建议：有界语义巡检 | 无机械信号仍进入语义队列；由当前智能体按核心Skill核实 | 不把脚本派发队列冒充无人值守大模型判断 |

最终采用原生补充模式：核心 Skill 负责判断方法，`retirement.py` 负责确定性取证与状态，已有项目库保留证据，GitHub工作流负责实际周期。没有安装额外Skill、模型、后台本地服务或治理平台。

## 运行闭环

本地任务或获准的远端手动触发 → 扫描当前入口及项目内依赖链 → 整段语义复核 → 保存保留/建议退役/历史保留/证据不足 → 必要时承接既有规则变更或治理预演 → 实际改后重扫。周期与 main 变更触发只在首次远端验收后另行决定。

扫描包含AGENTS、Skill正文与参考、Agent元数据和指针，源码只作为事实依据，不把源码段落当规则。保留整段标题、联合条件和例外，不拆成可自动删除的句子。归档、业务数据、临时目录、第三方与测试题库默认排除；断链、编码、上限、越界及符号链接均不被当成语义正确。

同一版本快照复用，未变文件证据复用；相同审阅可重试。条目身份由相对路径、从 H1 到当前节的标题文本路径和本节段落序号组成；正文与多跳依据只进入绑定版本，使同位置正文变化能够续接并重新复核。改标题、移动、拆合及前置插入/删除可能使续接标注失真，但当前文件哈希变化后所有受影响条目必须重新复核，不得沿用旧处置压制。复审采用7/30天默认期限和90天上限。已建议退役仍为待授权处置，不伪装实施完成；历史记录永不覆盖。

GitHub 的 `Retirement watch` 初始仅在 main 上手动派发，并要求显式确认本次 Issue 写入；main 推送和定时触发尚未启用。它只恢复本仓库、本工作流、main 成功运行的 SQLite 产物，维护一个 Issue 索引，不把源码原文贴入通知。记忆缺失时明示全量复核，损坏时停止。本地和云端实例不自动同步；本地数据库不上传。

## 验证契约与结果边界

先固定范围、状态与反例，再检查真实调用和副作用。新测试使用隔离合成项目，不使用业务数据或其他项目。

覆盖：完整依赖链、断链、锚点、明示退役引用、YAML指针、中文路径、链接正常但指导冲突的审阅闭环；只读、项目隔离、符号链接、越界、容量/编码缺口；去重、到期、依据变化、缺失文件重新出现、伪造摘录、旧快照、不得批准删除、CRLF/BOM。

机械分支对照：仅信号分支在“旧入口必须使用、现行依据宣布停用”中为零告警；最终分支仍生成完整语义复核项，并接受有两侧原文依据的“建议退役”，不改源文件。该结果证明闭环可承载这类判断，不证明程序独立理解开放中文。用于选方案的合成例不称独立留出；程序控制与实际当前仓库审阅分别记录。

验证工作流在 Linux 与 Windows、Python 3.12 隔离环境运行新旧全部 unittest、独立中文规则检查、核心 Skill 自测和远端巡检离线演练。正式 v0.2.0 Release 只在验证通过、工作流于 main 上被手动派发且显式确认 `publish_release` 后生成；main 推送本身不发布。失败记录保留在 Actions，不重写为成功。最终提交、运行结果和产物以 GitHub 实际回执为准，不在本文件预填未来成功。

## 人工确认与未实现边界

当前智能体负责开放语义复核，用户只裁定真实业务取舍。发布授权不是今后任意删除或生产规则变更的永久授权；本模块没有自动改文或删除功能。全局Codex部署副本、本地定时器、跨实例处置同步及独立模型评测不在此次实现中。

周期触发尚未启用；若首次手动验收后另行启用，仍须考虑 GitHub 定时延迟与公开仓库无活动时的自动停用，不能承诺硬实时或永久常驻，也不能用一次正常运行证明长期触发率。原有配音、外部业务平台与通用独立语义效度边界保持不变。
