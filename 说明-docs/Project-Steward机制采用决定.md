# Project Steward 机制采用决定

## 决定

工作台原生仓库治理模块是唯一确定性执行器，已替换早期隔离试用中的 `organize-tool`。`治理-governance/`只保存清单、预演和执行回执，不是软件或治理真源。

Project Steward 不作为依赖、执行器或事实库，不再启动完整工具选型。仅保留并已吸收下列确有增量的机制：

- 生产者；
- 活动消费者与消费者检查依据；
- 路径所有者；
- 生命周期；
- 证据强度。

Repomix 的仓库内容打包和模型读取职责独立保留，不参与文件分类、移动、归档、恢复或删除。

## 依据与边界

早期讨论发生时，工作台尚缺少完整的确定性文件治理执行链，因此曾把 `organize-tool` 作为隔离试用候选。当前原生模块已经提供盘点、缓存清单、预演、执行、恢复和删除精确授权，并有匹配回归测试；因此同一能力不再保留第二套正式实现。

该决定只裁决仓库治理工具与机制归属，不证明具体材料已经正确分类，也不授权移动、归档或删除任何文件。现行执行规则以[仓库治理标准](仓库治理标准-repository-governance.md)为准，实现边界以[当前实现状态](当前实现状态.md)为准。
