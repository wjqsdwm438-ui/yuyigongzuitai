# 仓库治理标准（可执行版）

## 目标与活动边界

活动区只放当前规则、当前源码、可复现测试定义和仍被消费的交付物。退役材料不得继续占据活动入口。确有历史价值的材料移入根目录 `归档-archive/`；该目录已写入 `.ignore`，默认搜索和模型扫描不加载，回查时必须显式指定路径。

归档不同于垃圾桶：没有历史价值的材料不能长期转存。经确认属于“重复或无效垃圾”、无活动消费者且不影响恢复的材料，进入单独的删除预演，使用该次预演编号批准后删除。

## 统一位置与命名

- 当前规则：放在其业务阶段目录，文件名不使用 `final`、`new`、`最新版` 区分版本；当前入口只保留一个，历史版本写明替代关系后归档。
- 源码：稳定工具进入 `源码-src/` 或对应项目源码目录；一次性探针随测试批次保存，不与稳定模块混放。
- 测试定义：保存测试对象、预期和判定方法；生成结果与定义分开。
- 历史证据：`归档-archive/<材料类型>/<YYYY-MM>/<原业务路径>/`，并由治理清单保存原路径、分类、依据和哈希。
- 阶段产物：采用 `<对象>-<阶段>-<用途>.<扩展名>`；随机运行编号可保留在机器产物中，但须由一份可读结果索引解释。

## 历史测试五类

每份历史测试材料必须结合测试对象、预期、结果和后续用途，归入且只归入一类：

1. `有效正面案例`：结果有效，能验证当前能力或防止回归。
2. `具有明确失败机制的反面案例`：失败原因已定位，可稳定复现或可教学。
3. `仍有诊断价值的负面结果`：尚不能稳定复现，但包含独特诊断证据。
4. `重复或无效垃圾`：重复、空、截断、被更完整结果覆盖，且无独特证据。
5. `证据不足的未知材料`：缺少对象、预期、结果或用途；只能保留或待确认，不能自动移动、归档或删除。

## 四步执行闭环

1. `治理盘点`：只读统计活动文件、退役信号、测试候选和次要代码指标。
2. 编辑治理清单：智能体结合真实内容和引用填写分类、依据与候选动作；拟归档或删除的条目必须记录生产者、活动消费者列表、消费者检查依据、路径所有者、生命周期和证据强度。仍有活动消费者、消费者字段不是列表、证据为弱或未知时停止。未知项逐次询问。对于 `cache` 目录内的 Numba 编译缓存，可用 `治理缓存清单` 生成逐文件候选，但仍不自动删除。
3. `治理预演`：生成准确源/目标、SHA256、字节数、冲突和恢复边界。目标占用、源目标交叉、越界路径、证据不足或分类不合规都会停止。
4. `治理执行`：执行前再次核对文件哈希。归档移动输出回执并可恢复；删除必须确认“重复或无效垃圾、活动消费者列表为空、不影响恢复”，再用该次预演编号单独批准。归档与删除不得放进同一次预演，避免不可恢复删除破坏移动回滚边界；删除回执记录批准编号。

示例命令（由助手实际运行，用户无需手写结构化数据）：

```powershell
python 工作台.py --项目 E:\yuyigongzuitai 治理盘点 --范围 设计 --输出 治理-governance\盘点.json
python 工作台.py --项目 E:\yuyigongzuitai 治理预演 治理-governance\候选清单.json --输出 治理-governance\预演.json
python 工作台.py --项目 E:\yuyigongzuitai 治理执行 治理-governance\预演.json --回执 治理-governance\执行回执.json
```

## 自主整理与停止条件

模型可自主盘点、查消费者、补齐清单、预演，以及执行已经明确为非核心的归档移动。下列情况必须停止并具体追问：材料为未知；多个当前版本互相冲突；活动消费者仍引用旧位置；目标已存在；恢复依赖不清楚；拟删除内容未获得本次预演编号批准。

Python 文件超过 500 行只列为“职责复核提示”。是否拆分必须再看职责、变更耦合、接口和测试，不能由行数直接判错。

## 唯一能力所有者

- Agent 按本标准负责开放语义判断；程序不根据名称、扩展名或时间替代判断。
- `源码-src/语义工作台/repository_governance.py` 是盘点、预演、移动、归档、删除和恢复的唯一执行器。
- 工作台分项目数据库保存历史决定、候选与状态；Git 保存源码历史。
- `治理-governance/` 是治理产物目录，不是另一套软件或事实库。
- `organize-tool` 的隔离试用已由原生执行器替代；`repo-maintenance` 不进入正式链。
- Project Steward 只提供生产者、消费者、路径所有者、生命周期和证据强度等机制来源，不安装、不执行、不保存项目事实。
- Repomix 只负责仓库打包、过滤和模型读取，不参与本标准定义的文件治理动作。
