# 当前实现状态（发布快照）

核心入口包含 Agent 设计、规则原子化、世界模型、规则变更、案例诊断、历史回查及回归验证的交付组织。设计、原子化、建模、变更和验证专项可一次接收多份材料并分别保留路径、内容和证据身份；案例诊断仍按单份案例材料处理。程序校验结构、来源和状态，不替代开放语义判断。

规则版本、证据与候选记录使用本地数据库；项目分库、历史保留、只读路径及备份机制保留。库、真实材料和本地验收日志不随本快照发布。

仓库治理已接入原生盘点、缓存清单、预演、执行和恢复命令，是本项目唯一确定性文件操作实现。它支持逐文件哈希、来源漂移与目标冲突停止、归档恢复、删除精确预演编号，并要求归档或删除条目提供生产者、活动消费者、消费者检查依据、路径所有者、生命周期和证据强度。归档与删除必须分开预演。

上述机械门禁及实际回执不证明语义分类正确，也不自行授予业务权限；逐文件以外的目录级原子操作、移动与消费者引用同步仍未实现。通用独立效度及减负尚未证明。未接通的“授权实施”专指通用业务规则文件写入与恢复，不包括仓库治理命令；完整世界模型治理和外部平台接入的未完成边界不因本模块可用而改变。

职责已经定版：Agent 按仓库治理标准负责语义判断；原生模块负责确定性文件动作；工作台分项目数据库保存历史决定；`治理-governance/`只保存清单、预演和执行回执。`organize-tool` 与 `repo-maintenance` 不进入正式链，Project Steward 不安装且不成为事实库。Repomix 1.18.0 独立负责把本地或远程仓库整理为模型可读输入，不参与仓库治理动作。

原开发机的状态记录、建设讨论与真实项目报告仅保留本地，不能据本快照伪造其运行证据。
