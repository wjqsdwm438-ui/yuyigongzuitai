## 仓库治理与能力边界

飞书上传已接通为独立 CLI 子命令 `飞书上传`：使用环境变量中的自建应用凭据获取
`tenant_access_token`，并将单个文件上传到显式指定的云空间文件夹 token。已覆盖预演、凭据缺失、
multipart 请求和成功响应解析测试；未在本次测试中调用真实飞书租户。通用“授权实施”仍不等于所有业务规则
写入执行器，飞书上传也不会自动发布或修改工作台规则。

仓库治理已接入原生盘点、缓存清单、预演、执行和恢复命令，是本项目唯一确定性文件操作实现。它支持逐文件哈希、来源漂移与目标冲突停止、归档恢复、删除精确预演编号，并要求归档或删除条目提供生产者、活动消费者、消费者检查依据、路径所有者、生命周期和证据强度。归档与删除必须分开预演。

上述机械门禁及实际回执不证明语义分类正确，也不自行授予业务权限；逐文件以外的目录级原子操作、移动与消费者引用同步仍未实现。未接通的“授权实施”专指通用业务规则文件写入与恢复，不包括仓库治理命令；完整世界模型治理和外部平台接入的未完成边界不因本模块可用而改变。

职责已经定版：Agent 按仓库治理标准负责语义判断；原生模块负责确定性文件动作；工作台分项目数据库保存历史决定；`治理-governance/`只保存清单、预演和执行回执。`organize-tool` 与 `repo-maintenance` 不进入正式链，Project Steward 不安装且不成为事实库。Repomix 1.18.0 独立负责把本地或远程仓库整理为模型可读输入，不参与仓库治理动作。
