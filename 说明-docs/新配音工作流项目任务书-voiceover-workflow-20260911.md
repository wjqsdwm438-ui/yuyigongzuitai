## 1. 项目目标与完成定义

将现有字幕能力演进为可从自然语言任务持续推进到成品的配音与字幕工作流：用户交稿，系统形成共同正文和可审核配音稿；人工通过现有本地配音页面合成、试听并交回定稿音频；系统据共同正文及同版音频生成字幕。

目标形态为：任务分型、两份交付级 Skill、一个执行 Agent、现有确定性代码和人工声音验收。Skill 承载任务操作与交付，Agent 处理开放语义，代码执行稳定转换及约束，不按节点新增 Skill 或 Agent。

正式迁移的前置是：工作台先通过本字幕项目的真实规则维护验证功能；相关规则完成原子化、组合关系审阅、实现对齐和实际运行验证。不能用存储字段、模板完整或机械测试数量代替语义验收。

项目完成必须同时满足：

1. 工作台能完成本项目真实规则的分析、修改、关联影响验证与历史回查，并交付有效规则，不只是登记材料。
2. 新配音型任务具备正式入口，无未登记环境变量旁路，正文不会被 TTS-WEAK 反写。
3. 读法、术语、数字、标注和语义停顿在全篇合成前有可执行处理；实际声音仍经过覆盖范围明确的验收。
4. 配音、音文比较及 FINAL 对齐承接同一份读法决定，生成各自支持的表示。
5. 两份 Skill 能由用户自然语言触发并完成交付、必要停止与恢复，用户不填写内部编号或 JSON。
6. 新链路通过本任务书的全回归与独立留出；旧录音字幕及应保留的独立工具能力不退化。
7. 与各自有效基线相比，结果质量达标，人工推动、返工和维护负担得到实际测量；不以更多停链换取表面正确率。

## 5. 用户工作流与两份Skill

### 5.1 配音型完整链路

```text
用户交口播稿
  → 必要的原稿转换 → 1.1机械归一化
  → 1.4非正文归属与无音频闭合 → 保留共同正文
  → 结合全文形成术语／读法决定和候选语义边界
  → 受控展开得到无标记配音稿 → 按展开结果校验语义段
  → 段内编译必要hotfix → 校验实际前端和输入
  → 配音稿、读法与边界清单交付，完成文本层审阅
  → 停在人工页面合成与声音验收
  → 交回实际使用文本、参数、试听结论和完整定稿WAV
  → 共同正文经1.5显示清理、1.7语义断行
  → 同版WAV生成WEAK → 2.1映射 → 2.2分类与任务型处置
  → FINAL对齐与既有终审 → SRT及范围明确的报告
```

全文理解在读法和停顿的局部判断之前提供上下文；最终边界须检查数字与术语展开后的长度和结构。不能机械规定“先做停顿后永不调整”，也不能因引擎token数把术语截断。

录音型保持原有效处理路线，包括其合法的WEAK与1.4.1用途；不强加配音稿生成或事前声音验收。1.7是字幕显示断行，不承担配音停顿规划。

### 5.2 两份Skill合同

| 项目 | 生成待审核配音稿 | 从正文与音频生成字幕 |
|---|---|---|
| 触发 | 用户交稿并要求生成配音输入 | 用户交回配音音频，或要求处理录音字幕 |
| 用户输入 | 原稿；已有闭合正文也可作为续接输入，但需核验身份和规则适用 | 配音型：共同正文、定稿WAV、实际合成文本和试听结论；录音型：原稿与原录音 |
| 正常动作 | 实际调用正文形成、读法、边界和标注工具 | 按任务型完成正文／显示／证据／对齐链 |
| 交付 | 无标记配音稿、必要标记合成输入、读法与边界审阅记录；可合成与待决部分明确区分 | 最终SRT、成品报告；未决或技术停止时交明确当前产物与恢复条件 |
| 默认停止 | 文本准备完成后停人工配音；真正业务未决保持未决 | 配音型实质音频错读停止重配；证据不足未决；技术失败按既有有限重试后停止 |
| 恢复 | 明确决定后重新生成受影响派生物；实质正文修订后重新派生两条分支 | 新WAV新运行；正文改动后更新所有受影响输入和判断 |

Skill写明触发、工具、输入、输出、停止、恢复及规则锚点，不复制宽度、分段、重试等规则数值。Agent提案和代码校验在配音能力实现时即具备，不能把Agent接入排在Skill功能完成之后。

## 6. 工程与语义合同

### 6.1 不可变任务型与正文隔离

在现有run配置事实机制上增加两值任务型。创建运行时由用户请求明确判定；续跑核验原值，运行中途修改拒绝。产物沿既有run身份关联任务型，不建立通用类型框架或逐文件新元数据系统。

旧运行按P0核实的版本与既有业务语义处理；没有可靠依据时不能靠当前目录内容猜类型。确定的录音旧运行保持原路线；切换为配音任务创建新运行。

| 层 | 必须实现的行为 | 必须有的验证 |
|---|---|---|
| 配置／entrypoint | 创建时固定任务型，续跑一致 | 缺失／非法取值按正式入口规则处理；中途修改拒绝 |
| registry | 配音型不要求正文校对WEAK，且不可选择TTS-WEAK作为1.4证据 | 无WEAK的配音输入合法；已有TTS-WEAK仍不可选 |
| 1.4 executor | 配音型直接闭合；绕过选择层也拒收非法正文证据 | 清除环境变量仍成功；强传TTS-WEAK拒绝且正文不变 |
| WEAK用途登记 | 配音型剥离正文合成用途，保留合法2.1/2.2证据用途 | 配音型不存在1.4.1用途；录音型合法用途仍在 |
| 2.2 executor／结果 | 经证据确认的配音实质错误停止重配，不能成功闭合 | 错误USE_SPOKEN不生效；等价与ASR噪声不误停 |

正式无音频路径落地时删除 `SUBTITLE_REVIEW_PHASE14_DIRECT` 旁路；不能让环境变量继续改变新合同。配音型禁止1.4.1正文合成，不是偶然未选择。

### 6.2 差异先分类，再按任务型处置

| 差异性质 | 录音型 | 配音型 |
|---|---|---|
| 逐字一致／可重算受控等价 | 正常闭合 | 正常闭合，不改共同正文 |
| ASR误识别，实际声音与目标一致 | 按证据保留正确内容 | 不停链重配，不按ASR改字 |
| 实质实词、数值、否定词或非预期增删重复，经直接证据确认 | 按既有规则采用真实口播或合法归一 | 明确重配停止结果；不通过改字幕迁就错误配音 |
| 无信息口吃、重启 | 按既有直接证据与条件归一 | 确认属于合成缺陷时重配；性质不明则未决 |
| 证据不足 | 节点有限复核后未决 | 同左 |
| 技术失败 | 既有有限技术重试后明确技术停止 | 同左 |

`bounded_local_spoken_difference`只提供受限位置和时间范围，不证明语义等价。没有ASR差异不等于读音无误；2.2仅兜可观察的差异，R8通过不表示声音验收通过。

无可对齐字符应按材料性质记录不适用或明确异常；不计入通过，也不能用这个分类悄悄排除真实正文。

### 6.4 读法选择与标注

读法选择优先级：本次明确覆盖、作用域适配的已确认约定、可重算规则、词组词典和上下文候选。g2pW等输出仅作候选；Agent在有效规则内可唯一判断时形成局部决定并由代码核验。真实专名或业务歧义才提交用户，不把所有模型候选逐条转人工。

常规数值用算法，年份／时长／编号／型号按明确类型分派，二／两和术语惯读依有效口径。局部决定不自动提升为全局词典；同词形不同含义可以有不同读法。

稀疏hotfix用于需要控制的具体出现位置，不因字表命中就全文注音，不预设固定密度上限。先在无控制标记、已受控展开的文本上规划语义段，再在段内编译标记；之后检查真实前端分块及模型输入容量。超限不得裁开控制token或保护对象。

编译器使用实际加载tokenizer的特殊token集合，检查源位置、目标音节到token的编码、重叠与重复处理；不写死token ID或自造拼音清单。合法token不能证明拼音组合和目标读法正确。

源文自带方括号与程序控制标记分开标识；不能将原文中的类似控制串自动执行。保留原文来源与映射，标注不得静默删词或重复原字。

### 6.5 全文语义停顿与差异约束

上下文可容纳时读取全文；长文按真实章节、段落和必要相邻原文分批，携带已确认术语、读法、指代和并列结构。摘要只辅助导航，不能替代作决定需要的原文。检查跨批术语一致性、同词异义、指代及列举承接。

代码提取显式结构和保护对象；Agent可以在原标点之外提出停顿。每个编辑绑定原文版本和字符位置、原边界、候选标点或合成边界及语义依据。不得未经决定合并、重排或改写原语段；允许跨段阅读上下文。

三类差异分别验证：

- 机械变化：校验允许的标点、空白、边界变化；其余字符序列、次数和顺序保持。保护对象不被拆开。
- 受控读法变化：精确源跨度与规则匹配，可以重算；数值、符号、中文单位、合法二／两等不能仅凭“在允许区域”放行。
- 其他变化：需有适用于本次的明确决定；实质改词走正文修订，重新派生，不能以适合朗读为由润色。

标点变化也可能改变算式分组、修饰和列举含义，字符覆盖检查只是必要条件。语义审阅检查含义和边界，声音听评检查读音、连读、停顿和自然度，两者都不可省。

### 6.6 合成入口、离线资源与最小交接

基线采用先前实际使用的 `gradio_app.py → main_cosyvoice.py` 本地服务。页面的参考音频、参考文字、合成文字和txt3是实际参数；当前无显式语速和text_frontend控制。第一版不依赖调速，不预设默认前端必须关闭。

P0核实wetext版本、当前构造行为及已缓存FST。需要离线构造时复用其本地资源参数，完成断网且禁止hub调用的启动与组件测试；资源缺失给出明确错误，禁止测试时隐式联网补资源。所有新增依赖在项目隔离环境中处理。

R7保留三段证据：

1. 组件传递：固定hotfix样本经过实际Normalizer及tokenizer，验证预期文本和特殊token；不要求所有TN输入原字节不变。
2. 发音效果：同句无标记与正确标记比较，听评目标音、邻字、完整性和韵律；包含已知错误的验收器检查样本。
3. 实际交付：观测实际请求文本、完整前端处理与分块、必要token信息及返回WAV对应，证明不是只测一个替代调用。

被审定为一个合成段的单次提交，完整前端输出应恰为一个文本段；不得有未经规划允许的额外分块及块后静音。tokenizer-only分段结果不作为完整TN路径的替代证据。

记录每次实际txt3，不能用页面默认值代替观测。服务对每个返回块追加静音，含末块；追加静音总量与模型自带停顿分别核验。txt3不是整个配音停顿布局。

最小任务记录包含实际txt1／txt2、参考音频身份、txt3及本次返回音频关联；可用既有任务记录或一条任务级JSONL，不建设全局日志。仅在必须证明返回文件一致时使用一次音频内容校验；长度或事后自述不能单独证明实际提交身份。

交回音频时同时交回实际使用文本。标注、读法、标点与分段变化重新校验；实质正文变化触发正文修订。实际文本或对应关系无法确认时，不宣称沿用了审定输入。

若现有入口确实不能表达必要控制，以固定失败证明后实施最小接入改动。测试脚本调用合成不改变生产默认人工配音停止点，不自动引入第二套生产入口。

### 6.7 声音验收与恢复

配音前读法审阅只承诺文本层。合成后的试听仍检查读音、术语连读、漏读、非预期重复、呼吸和接缝；hotfix不能使读音试听职责消失。

试听记录保留WAV关联、覆盖范围、问题、处置和审核者。未覆盖范围标记未验证；发现关键问题未解决则不能宣称正式声音通过。ASR、VAD、静音检测不能代替听评。

更换WAV创建新字幕运行，重新执行1.5、1.7、WEAK、2.1、2.2、FINAL；1.7仍作语义判断。旧音频的试听结论和时间证据不得用于新音频，但历史记录保留，不删除为“作废”。

在网页改了实词，先修订共同正文并重新派生；仅改变实际合成方式也需要新声音验收。中断恢复必须核验当前输入与证据，不能把文件存在当作阶段完成。

## 9. 样本、诊断比较、预算与停止

### 9.1 样本与独立性

短句定位机制，完整段落验证上下文与累积影响，完整课程验证最终交付。已有三篇调试课程和已暴露试验结果归入开发集；不能将同篇另一段当作完全独立留出。

P2由评测组织者固定留出分组与答案，开发执行者在P7前不查看其内容或答案。相同参考声音的新课程可以验证内容泛化，但不能声称跨音色泛化；主题、讲者和参考声音的未覆盖维度单独列出。材料一旦用于调参，就转开发集，最后重新准备留出。

每例先确定语境、允许结果、禁止结果、是否应停、判据及来源。目标读法和语义边界不能由受测Agent同时生成并评分；允许变体由有效规范或领域判断预先确定。机械、语义、声音和时间的标准分别表达。

### 9.2 诊断矩阵

| 组别 | 目的 |
|---|---|
| A：原文输入 | 观察现有引擎基线 |
| B：人工确认读法与边界的候选 | 排除自动判断，验证控制与引擎能力 |
| C：Agent自动生成候选 | 检查规则、工具和判断组成的完整能力 |

B失败优先查控制实现、参考条件或引擎；B通过而C失败优先查自动判断与转换。它们是诊断配置，不虚构综合排名。正式运行方式另比较旧录音链与新Skill，以及配音人工做法与新配音Skill。

配对比较固定参考音文、文本和参数；一次只改变明确因素。盲评隐藏组别、随机呈现次序，重复生成保留全部音频、失败请求和技术错误。已确认错读／漏读／错误分段的音频用于检查验收者是否能发现问题，不能只检查正确音频。

ASR、VAD和静音测量只能辅助定位；声学验收以听评为准。争议项作独立复核，不把每个节点变成多Agent互审。

- 第一轮：6条完整短句、2段真实长段；A/B/C三组，各3次，共72次合成尝试。
- 固定一种参考声音；第二参考声音仅对最多2个明确问题样本复核，最多再18次尝试。
- 人工听评与记录累计预算120分钟；记录覆盖率、样本时长和未听部分。
- 以尝试次数计数，技术失败占用尝试预算；有限重试也不得悄悄增加总量。
- 达到次数或人工时间任一上限即结束该批，输出结果与阻断；未覆盖标未验证，不选最好的一次代替全部结果。
- 关键问题未解时停止受影响能力放行；若需新实验，先明确新假设与有限预算，不无界扩样。

P7另按P0记录的完整课程数量、时长和配对方案编制总预算；不拿短段试验代替全课验收。生产不要求每篇全文A/B，开发期已稳定的规则正常使用，新词或高风险结构按明确策略作局部预验证。

## 10. 验收、替换与恢复

### 10.1 分阶段检查频率

局部修改跑直接回归及共享调用方；规则、映射、任务路由变化扩大关联覆盖。P7执行R1—R11全回归与留出；不要求每次小改都重新合成所有课程。

### 10.2 放行条件

1. 所有必要机械和隔离合同通过，无可绕过的任务型、来源或正文写权限缺口。
2. 固定关键样本无已知未解决正文、数字、否定词、目标读音或严重漏读问题；不能以平均分抵消关键失败。
3. 正常样本显示、声音自然度及时间质量不低于对应有效基线，合理变体按P2标准判断。
4. 误停、漏停、未决、技术失败、未验证分别计数。只给未停止样本算正确率不合格。
5. 时间验收优先沿用现有有效业务标准；缺失指标在P2由业务标准与独立基线确定，不能看完候选后改阈值。
6. 正文、配音稿、声音、SRT、人工主动处理分钟数、等待时间、返工与重配次数分别报告。开发成本与日常生产成本分开。
7. R1用真实成品证明工作台功能，R11用任务轨迹证明Skill可持续推进，二者不以字段或测试数量替代。

“未发现问题”限定于实际覆盖范围，未通过或未验证的关键能力不作为正式可用能力发布。用户明确接受局部风险也要限定该次范围，不能据此宣布通用回归通过。

### 10.3 替换与回退

P7通过后才替换对应入口；先在有限真实任务中使用，保留旧有效路径和原测试证据。新链失败时恢复该任务可用的旧路径，不覆盖旧材料或旧规则历史。候选产物、重配音频和失败测试不得冒充正式交付。

新增正文修订或WAV意味着相关下游结果需要重新生成与验收；不开展本期范围外的自动段级重配优化。删除重复入口只针对已被验证替代的机制，不顺带清理整个旧项目。

## 11. 依赖取舍与最小实现原则

| 能力 | 优先复用 | 新增条件 |
|---|---|---|
| 数字转换 | 共享`_number_to_chinese`及已存在结构识别 | 只有现有核心不适合维护且比较有明确收益，才引入通用数值库；不先安装再迁移 |
| 多音字候选 | 当前可用词典、局部决定与pypinyin能力 | g2pW仅在真实长尾缺口及本地兼容验证后引入 |
| 术语保护 | 已有保护结构、坐标与投影机制 | 不因需要词内保护就默认新增jieba或另造分词层 |
| 文本归一化 | 当前wetext与已确认规则 | 本地资源构造优先；不重复TN造成不可控变化 |
| 配音与对齐 | 已有CosyVoice、WEAK和FINAL | 只补实际路径必要的参数、记录或表示适配 |
| 记录与计时 | 当前任务记录、测试报告及一份简单耗时表 | 不建计时工具、审批平台或全局日志 |

并非“开源能做”就全部引入。新增库须回答具体缺口、许可与版本、离线资源、Windows适配、接入成本和可验证收益；局部技术探针不能自动取得安装或付费调用授权。
