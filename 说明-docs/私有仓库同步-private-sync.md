## Repomix 模型读取入口

Repomix 与仓库治理分工固定：Repomix 生成可供不同模型读取的仓库快照，工作台治理模块管理活动文件、历史材料、移动、归档、恢复和删除边界。两者不互相替代。

项目入口 `脚本-scripts/仓库模型打包.ps1` 固定调用 Repomix 1.18.0，配置来自根目录 `repomix.config.json` 和 `.repomixignore`。输出只进入 `导出-exports/`，不成为新的事实源或 Git 提交对象。安全检查保持开启；处理远程仓库时不使用 `--remote-trust-config`，因此不加载远端仓库提供的 Repomix 配置或处理器。私有远端是否可直接打包取决于该次 Git 凭据环境，必须以实际运行结果为准。

2026-09-15 实际验证：本地工作台按项目配置打包 47 个文件、96,198 tokens，安全检查通过；随后从 `yamadashy/repomix` 的 `main` 分支远程下载并按本地配置打包 2 个匹配文件、30,501 tokens，安全检查通过。两次均使用 Repomix 1.18.0。该结果证明本地与公开远端入口可用，不证明当前环境已经取得三个私有仓库的远端克隆凭据。

## 每批同步闭环

1. 读取目标仓库可见性、分支及当前提交；核实本次已授权范围。
2. 在本地准备显式文件清单、差异和必要的本地来源映射；映射中的私有定位不进入仓库阅读版。
3. 检查实际待同步文本、敏感内容、UTF-8、相对链接、引用一致性及所涉测试。文档更新不冒充代码或业务验证。
4. 基于刚读取的远端版本同步选定文件；不得强推、覆盖未知变更或带入本地原始历史。
5. 从远端重新读取文件并逐字比对，复查实际可见性是否符合本次授权，报告实际提交及剩余事项。接口成功、本地修改和远端完成分别记录。

不启用后台自动同步。后续每批变更沿用上述过程；源码、状态和阅读入口在同批更新，避免远端说明落后于实际交付。
