# 技能审阅与修改通用 SOP

**适用边界**：审阅技能、规则文本及配套文件。本 SOP 约束审阅过程，不自动成为被审对象的规则。

1. **确定权限与基线。** 明确对象及版本、有效要求和允许操作，区分事实、已采纳决定与候选建议。授权按所指动作判断，既有明确授权有效，普通确认不扩大范围；验证及下游同步均受此约束。规则冲突按环境指令层级及明确的替代、撤销关系处理；仍不明确时，仅暂停受影响部分并澄清。

2. **核对任务契约。** 明确适用场景、输入、输出、职责边界和完成条件，判断技能何时应介入、何时应退出。

3. **审核语义。** 对照基线查找歧义、冲突、缺漏及无依据要求，检查能力、义务强度和适用范围是否改变。未获准改变的语义与定位值保持不变；获准改变的核对映射及关联影响。仅对疑点追溯相关版本。

4. **审核结构。** 每项规则集中定义，条件与例外就近说明，关联处引用；主流程、分支和参考材料各归其位。合并重复表达，删除有依据的冗余或失效说明，临时部署事实归入配置或维护记录。删除按影响验证，证据不足处列入未验证范围。

5. **核对运行条件。** 检查元数据、入口、依赖、引用、工具权限和环境差异。明确哪些边界由机制保证、哪些依赖指令遵循；必要时建议环境层限制。

6. **验证行为。** 从有效要求确定判据，覆盖正常、边界、失败及不应介入的场景，检查输出、必要轨迹和副作用。历史失败输出用于构造反例，不直接作为验收基准。判据在运行前冻结：行为标准由用户裁定，不由被测文本反推；判据有误记新版本，不改旧档。评分后置且中性，提示中不出现判据线索。按影响选择方法：
   - **静态检查**：判断结构与规则，不据此宣称行为通过。
   - **独立运行**：每次用独立新会话处理单个用例，隔离无关历史提示，记录模型、环境、输入和结果；批量串案会悬置单次回复契约，不作为部署行为证据；结论限于已测场景。
   - **受限验证**：涉及未授权操作时采用隔离测试，或仅提供测试方案。

   行数、关键词和自评不能单独证明行为改善；按形态清单判分，不采代理自评；评分者与被测文本同源时，须抽查原始运行记录；逐次归档输入、回复全文、工具轨迹与版本哈希。

7. **交付审核结论。** 结论锚定版本，问题按影响排序，区分必须修复与可选优化。过程中保留的冲突、疑点和未验证项，在交付中再现或注明销案依据。基线存疑且影响判断时，提出一个最小澄清问题，不默选一边。行为的默认取向（保留、提问或展开）由用户裁定，不代选。每项问题有依据、结论有相应证据、未决项有明确说明，即完成审核。仅有审核授权时，到此结束。

8. **按授权修改并复核。** 保存可恢复基线，确定停止条件，实施最小充分修改，必要时整体重组；改动优先以现行正式版加单条差分呈现，不用过时基线整篇拼装，吸收意见后做丢失检查，吸收过程引入的退步登记为吸收回归。同步受影响的引用与部署，保留明确的环境差异及无关改动。修改后读回并针对性验证。备份在各环境编辑前独立取快照并以哈希锚定；记录材料稳定后再建立，避免来源漂移拒收。部署按环境逐一备份、写入、回读比对并冒烟，随后进入监测窗口，真实使用的失败样本按本流程回炉；单次观察不构成增加条款的依据。达到停止条件时，按授权及可恢复性回滚或保留现场，并报告。

**交付包含**：结论及版本、问题与建议、验证方法及结果、未验证范围。
